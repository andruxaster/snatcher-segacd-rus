# Движок Snatcher (Sega CD, USA): что известно

Заметки по разведке. Адреса — память под-процессора (PRG-RAM), если не
сказано иное. Диск: redump *Snatcher (USA)*, 21 дорожка, первая — данные
(Mode 1, 2352 байта на сектор), SHA1 дорожки 1
`1f4164205ed736a0d9a03eb7972868e9aa737d35`.

## Файлы

ISO9660 на дорожке 1; игра открывает файлы **по имени** (таблица имён в
`SUBCODE.BIN` и в загрузочной области), поэтому файл можно увеличить в
пределах его «слота» (секторы до следующего файла; у `SPxx.BIN` и
`SUBCODE.BIN` это 27 секторов = 55 296 байт) или переложить в конец дорожки
и поправить каталог. `tools/cdimage.py` правит файлы на месте: пишет
секторы, обновляет размер в записи каталога (LE и BE) и пересчитывает
EDC/ECC (проверено на нетронутых секторах — совпадает).

| Файл | Что это |
|---|---|
| `SUBCODE.BIN` | программа под-процессора, грузится по `$D400` (файл `0xCF76` байт → до `$1A376`) |
| `SP00`–`SP38.BIN` | сценарий: байт-код + текст, грузится по `$1A800` |
| `PCMLD_01.BIN` / `PCMLT_01.BIN` | голоса (8-бит PCM 16 кГц) и их индекс |
| `DATA_*.BIN` | графика сцен |

Адрес загрузки `SUBCODE` найден по таблице переходов в начале файла
(`jmp $D4C4`, …) и подтверждается `jsr $107DC` = смещение `0x33DC` в файле.

## Сценарий `SPxx.BIN`

- `0x0000`–`0x37FF` — байт-код сцены.
- `0x3800`–конец — строки. В памяти текст начинается с `$1E000`
  (`$1A800 + 0x3800`).
- Строка: ASCII, конец `0xFF`, перенос строки `0xF2`. Прочие `0xF0`–`0xFE` —
  коды движка (`0xF9`/`0xFB` — выделение цветом, `0xEC`/`0xEE`/`0xF0` —
  значки кнопок по раскладке, `0xF4`, `0xF6`, `0xFA`, `0xFC`, `0xFE` — пока
  не разобраны). Байты `0x80`–`0xEB` в тексте игры не встречаются.
- Байт-код ссылается на строку **16-битным смещением от начала текста**
  (адрес строки = `$1E000 + смещение`). Каждая строка во всех 39 файлах имеет
  ссылку. Типичная форма: `43 20 00 NN <смещение>` (вывод реплики; `NN`,
  видимо, говорящий/портрет), встречаются и другие опкоды (`42 22 00 08`,
  `00 23 00 1x`, …). Полный разбор байт-кода — следующий шаг: поиск ссылок
  по шаблону даёт ложные совпадения.
- Смещение 16-битное: до 64 КБ текста на файл; сейчас самый большой текст
  37,5 КБ.

## Вывод текста

- `SUBCODE` `$13ADE…` (файл `0x66C0`): читает строку с `$1E000 + ($9746)` в
  буфер `$9750`; байты `< 0xF8` копирует как есть, `0xEC`/`0xEE`/`0xF0`
  заменяет символом кнопки, `0xF2`/`0xF4`/`0xF6`/`0xFF` — управление.
- `$13C04…` (файл `0x6804`): цикл по буферу; для символа
  `индекс = код − 0x20` → `$13E9C` рисует глиф, `$13F86` прибавляет ширину.
- Шрифт: `$14B7C` (файл `0x777C`), 102 глифа 8×8, 1 бит на пиксель, строка
  на байт; ширины: `$14EAC` (файл `0x7AAC`), по байту на глиф. Шрифт
  пропорциональный (строчные 6–7 px, «i» — 4). Во «флаге моноширинности»
  `$9728` ширина всегда 9.
- Глифы рисуются в битовую карту `$BE000` (Word RAM).

## Кириллица

`tools/cyrfont.py`: коды `0x90`–`0xAF` А–Я, `0xB0`–`0xCF` а–я, `0xD0` Ё,
`0xD1` ё. Буквы, совпадающие с латинскими по начертанию (А В Е К М Н О Р С Т
Х, а е о р с у х), берут глиф игры; остальные нарисованы в её стиле.
Ширина = правый пиксель + 2, как у латиницы игры.

`tools/fontpatch.py`: две `lea table.l,a5` (`$13EB8` — шрифт, `$13F94` —
ширины) заменены на `jsr` к вставкам, которые для индекса `≥ 0x70` берут
наши таблицы. Вставки (2 × 20 байт), 66 глифов (528 байт) и 66 ширин
дописаны в конец `SUBCODE.BIN`: `$1A376`–`$1A5F0`, свободная память до
`$1A800`, где начинается сценарий.

## Проверка

`tools/emurun.py` — libretro-хост без окна (из проекта pepa), по умолчанию
ядро Genesis Plus GX; нужен BIOS Sega CD (USA) — `bios_CD_U.bin` в папке
BIOS. Скрипт кнопок: `<кадр> press:<кнопка>` / `release` / `shot`. От
включения до первой реплики Мики — около 6300 кадров (Start на заставке,
затем B каждые 60 кадров).

## Не разобрано

- формат байт-кода сценария (точные длины опкодов);
- откуда табличка с именем говорящего («Mika»);
- меню действий и предметов (слова в начале текста `SPxx`, ширина окна
  меню);
- графика с надписями, экраны сохранения и опций;
- ширина строки в окне диалога (на глаз ~29 латинских символов).
